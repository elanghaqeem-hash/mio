# TP-0.56 — Portable Signer Audit Verification Bundle

Status: implementation candidate pending PR/CI validation

## Goal

Allow Mio's signer trust audit history to be exported and independently checked without granting access to Mio storage, model runtime, private signing keys, or lifecycle controls.

TP-0.55 made signer trust history tamper-evident inside Mio. TP-0.56 makes that evidence portable.

## Portable bundle

The export format is:

`MIO_SIGNER_TRUST_AUDIT_BUNDLE_V1`

A bundle contains:

- schema and format identifier;
- export timestamp;
- TP-0.55 source verification snapshot;
- public signer records;
- complete retained signer-trust audit events in oldest-to-newest order;
- deterministic SHA-256 digest of the complete bundle body.

Only public signer material is exported. No private signing key is stored, copied, imported, or generated by this workflow.

## Export gate

`SignerAuditPortableBundleService.exportBundle()` first executes the live TP-0.55 audit verifier.

If the live audit state is `CORRUPT`, export is blocked.

This avoids creating an apparently authoritative portable package from a trust store that Mio already knows is inconsistent.

The exporter is also bounded by the existing signer/audit limits:

- maximum 500 signer records;
- maximum 10,000 audit events;
- missing indexed signer or event data blocks export.

After building the bundle, Mio runs the portable verifier against its own output before returning it.

## Deterministic bundle digest

`bundleSha256` is SHA-256 over stable canonical JSON for the bundle body, excluding `bundleSha256` itself.

With an unchanged audit state and a fixed `exportedAt`, the digest is deterministic.

The digest detects accidental or partial modification after export. It is not a secret MAC and is not a digital signature.

## Portable verification

`verifyPortableSignerAuditBundle()` is storage-independent and checks:

1. schema and format kind;
2. bounded signer and event counts;
3. bundle SHA-256 digest;
4. duplicate signer identities;
5. public-key bytes against deterministic `p256:<SHA-256(SPKI DER)>` key identity;
6. audit event schema and sequence;
7. deterministic event hashes;
8. event hash-derived IDs;
9. predecessor hash links;
10. TP-0.54 legacy unchained compatibility;
11. latest audit status/label against exported signer state;
12. signer records against audit-history presence;
13. source verification event count and latest-event hash.

Result states are:

- `EMPTY`
- `VALID`
- `LEGACY_UNCHAINED`
- `CORRUPT`

## Offline CLI verifier

A standalone Node utility is included:

```bash
node scripts/training/verify-signer-audit-bundle.mjs <bundle.json>
```

The CLI:

- requires no Mio storage;
- requires no application server;
- requires no network;
- requires no private key;
- prints a JSON verification result;
- exits non-zero when the bundle is `CORRUPT`.

Self-test:

```bash
node scripts/training/verify-signer-audit-bundle.mjs --self-test
```

The Training Runner Contract validates both JavaScript syntax and this self-test in CI.

## Settings workflow

`Signer Trust Audit Integrity` in Settings includes `EXPORT VERIFICATION BUNDLE`.

Export is disabled when the live verification state is `CORRUPT`.

The downloaded filename includes the export timestamp. The operator can give that JSON file to another verifier without sharing Mio application storage.

## Regression coverage

`src/tests/signerAuditPortableBundleTests.ts` verifies:

- complete portable export;
- chronological event sequence;
- signer-state consistency;
- successful independent verification;
- deterministic digest with fixed export timestamp;
- event payload tamper detection;
- public-key substitution detection;
- bundle digest tamper detection;
- unsupported bundle-kind rejection;
- fail-closed export when live TP-0.55 audit is corrupt.

The suite is registered in `src/tests/runAllTests.ts`.

## Important trust limitation

TP-0.56 proves **internal consistency of the exported package**. It does not by itself prove that a package originated from a particular Mio installation at a particular external point in time.

A party capable of replacing the entire JSON package can also recompute ordinary SHA-256 values. Therefore:

- `bundleSha256` is tamper evidence for a known bundle fingerprint;
- it is not a notarization;
- it is not a remote attestation;
- it is not a transparency-log inclusion proof;
- it is not an offline authority signature.

External anchoring, hardware-backed attestation, transparency logging, or a separately governed audit-bundle signing authority should be implemented as a future checkpoint rather than implied by this one.

## Security boundary

TP-0.56 does not:

- expose private signing keys;
- modify signer trust;
- trust or revoke a signer;
- rotate keys;
- import bundle state back into Mio;
- train a model;
- benchmark a model;
- promote a model;
- activate a model;
- publish or deploy a model;
- contact a remote verification service.

The portable verifier is read-only.
